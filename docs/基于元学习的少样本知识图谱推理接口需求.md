## 统一约定

### 响应壳

网关若已统一为 `code/OK`，也可返回：

```json
{"code":"OK","message":"success","requestId":"req_xxx","data":{}}
```

本文默认写 **snake_case 业务字段** 的 `status` 壳（与历史需求文档一致）；联调前与网关确认一种即可，前端可双兼容。

```json
{"status":"ok","data":{},"error":null}
```

失败：`status=error`（或 `code≠OK`），`error`/`message` 为可读原因，HTTP `400/404/500`。

鉴权：`Authorization: Bearer <token>` + `X-Request-Id`（与现网关一致）。

### 公共对象

**三元组 `triple`**

```json
{"h":"李明","r":"合作发表于","t":"ACL"}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| h | string | 头实体 |
| r | string | 关系 |
| t | string | 尾实体 |

**Episode / 任务 `episode`**

```json
{
  "task_id": "episode_1",
  "relation": "位于",
  "n_way": 3,
  "k_shot": 2,
  "support": [{"h":"清华大学","r":"位于","t":"北京"}],
  "query": [{"h":"复旦大学","r":"位于","t":"?"}]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| task_id | string | 任务 ID（同一次 build 内唯一） |
| relation | string | 本 Episode 主关系（查询待补全关系） |
| n_way / k_shot | int | 构建时使用的参数回显 |
| support | triple[] | 支持集（K-shot） |
| query | object[] | 查询集；`t` 可为 `"?"` 或缺省，表示待推理尾实体 |

**推理预测 `prediction`**

```json
{"h":"陈刚","r":"合作发表于","t":"ICLR","score":0.86}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| h / r / t | string | 预测三元组 |
| score | float | 置信度，建议 `[0, 1]` |

| 步骤 | 功能点 | 接口 | 说明 |
| --- | --- | --- | --- |

| ③ | 新知识快速推理 | `POST /api/v1/meta-kg-reason/relations:infer` | **必须带 `model_id`**；建议带上一步的 `build_id` |

| default_model_id | string | 默认选中，如 `maml` |
| items | object[] | 模型列表 |

## 二、少样本任务构建

### 2. 构建 Episode

`POST /api/v1/meta-kg-reason/episodes:build`

从知识库采样关系与三元组，构造 N-way K-shot 少样本**推理**任务。**必须绑定第 ① 步所选模型**（不同模型可对应不同采样策略 / 缓存键，至少回显 `model_id`）。

#### 2.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| model_id | string | **是** | 来自模型库，如 `maml` |
| n_way | int | 否 | 关系类数，默认 `3`，建议 `[1, 8]` |
| k_shot | int | 否 | 每类支持样本数，默认 `2`，建议 `[1, 10]` |
| n_query | int | 否 | 每任务查询数，默认 `1`，建议 `[1, 5]` |
| task_count | int | 否 | Episode 个数，默认 `5`，建议 `[1, 20]` |
| seed | int | 否 | 随机种子，便于复现 |
| graph_id / graph_space | string | 否 | 采样图；缺省用服务默认业务图 |
| relation_whitelist | string[] | 否 | 仅从指定关系采样 |

```json
{
  "model_id": "maml",
  "n_way": 3,
  "k_shot": 2,
  "n_query": 1,
  "task_count": 5,
  "seed": 42
}
```

#### 2.2 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| build_id | string | **构建批次 ID**，第 ③ 步建议必传 |
| model_id | string | 回显 |
| n_way / k_shot / n_query / task_count | int | 实际使用参数 |
| episodes | episode[] | 任务列表 |
| graph_space | string | 可选，实际采样图 |

```json
{
  "status": "ok",
  "data": {
    "build_id": "build_8f3a2c",
    "model_id": "maml",
    "n_way": 3,
    "k_shot": 2,
    "n_query": 1,
    "task_count": 2,
    "episodes": [
      {
        "task_id": "episode_1",
        "relation": "位于",
        "n_way": 3,
        "k_shot": 2,
        "support": [
          {"h": "清华大学", "r": "位于", "t": "北京"},
          {"h": "北京大学", "r": "位于", "t": "北京"}
        ],
        "query": [{"h": "复旦大学", "r": "位于", "t": "?"}]
      }
    ]
  },
  "error": null
}
```

#### 2.3 错误

| 场景 | HTTP | 说明 |
| --- | --- | --- |
| 缺少 / 非法 `model_id` | 400 | `error` 提示可选 model 列表 |
| `model_id` 未 ready | 400 | 模型不可用 |
| 图数据不足以采样 | 400 / 422 | 说明缺关系或样本不足 |

```bash
curl -sS -X POST "$BASE/api/v1/meta-kg-reason/episodes:build" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model_id":"maml","n_way":3,"k_shot":2,"n_query":1,"task_count":5,"seed":42}'
```

## 三、新知识快速推理

### 3. 对新关系快速推理

`POST /api/v1/meta-kg-reason/relations:infer`

用户为**知识库新增关系**提供少量标注样本（support）与待推理头实体（query_heads），在已选元学习模型上快速适配并输出预测三元组。

前端页面顺序要求：先有 `model_id`，再有成功的 `build_id`（或等价的 episodes 上下文）。算法侧：

- **推荐**：`model_id` + `build_id` + 新关系 support/query（用构建批次做元上下文 / warm-start）  
- **兼容**：仅 `model_id` + support/query（无 build 时降级，但需在响应 `mode` 中标明 `standalone`）

#### 3.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| model_id | string | **是** | 与构建时一致 |
| build_id | string | 强烈建议 | 来自 `episodes:build`；缺失时允许 `standalone` |
| relation | string | **是** | 新关系名称，如 `合作发表于` |
| support | triple[] | **是** | 少量正例，建议 ≥1，推荐 ≥3 |
| query_heads | string[] | **是** | 待预测头实体列表 |
| top_k | int | 否 | 每个头实体返回候选尾实体数，默认 `1`，范围 `[1, 10]` |
| seed | int | 否 | 复现 |
| task_id | string | 否 | 指定使用 `build_id` 内某一 Episode 作上下文 |

`support` 中 `r` 可省略，服务端用 `relation` 回填。

```json
{
  "model_id": "maml",
  "build_id": "build_8f3a2c",
  "relation": "合作发表于",
  "support": [
    {"h": "李明", "t": "ACL"},
    {"h": "王芳", "t": "NeurIPS"},
    {"h": "赵强", "t": "AAAI"}
  ],
  "query_heads": ["陈刚", "周晓", "林伟"],
  "top_k": 1
}
```

#### 3.2 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| model_id | string | 回显 |
| build_id | string \| null | 回显 |
| relation | string | 回显 |
| support_count | int | 实际使用的支持样本数 |
| mode | string | `with_build` \| `standalone` |
| predictions | prediction[] | 推理结果（按 score 降序或按 query_heads 顺序） |
| adapted_model_id | string \| null | 可选：本次适配后的临时模型/检查点 ID |
| elapsed_ms | int | 可选 |

```json
{
  "status": "ok",
  "data": {
    "model_id": "maml",
    "build_id": "build_8f3a2c",
    "relation": "合作发表于",
    "support_count": 3,
    "mode": "with_build",
    "predictions": [
      {"h": "陈刚", "r": "合作发表于", "t": "ICLR", "score": 0.86},
      {"h": "周晓", "r": "合作发表于", "t": "NeurIPS", "score": 0.81},
      {"h": "林伟", "r": "合作发表于", "t": "ACL", "score": 0.79}
    ],
    "adapted_model_id": null,
    "elapsed_ms": 420
  },
  "error": null
}
```

#### 3.3 错误

| 场景 | HTTP | 说明 |
| --- | --- | --- |
| 缺 `model_id` / `relation` / `support` / `query_heads` | 400 | |
| `build_id` 不存在或已过期 | 404 | 提示重新构建任务 |
| `build_id` 与 `model_id` 不一致 | 400 | 必须与构建时模型一致 |
| support 为空 | 400 | |

```bash
curl -sS -X POST "$BASE/api/v1/meta-kg-reason/relations:infer" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model_id": "maml",
    "build_id": "build_8f3a2c",
    "relation": "合作发表于",
    "support": [
      {"h": "李明", "t": "ACL"},
      {"h": "王芳", "t": "NeurIPS"},
      {"h": "赵强", "t": "AAAI"}
    ],
    "query_heads": ["陈刚", "周晓", "林伟"],
    "top_k": 1
  }'
```

## 五、联调顺序建议

1. `GET .../models` → 前端渲染模型库，用户选择 `model_id`  
2. `POST .../episodes:build`（带 `model_id`）→ 展示 Episode，保存 `build_id`  
3. `POST .../relations:infer`（带同一 `model_id` + `build_id` + 新关系 support/query）→ 展示预测表  

耗时：`infer` 建议同步返回（目标 &lt; 60s）；若需异步，可另增 `job_id` + `GET /api/v1/jobs/{job_id}`，首期可不做。

`build_id` 建议服务端缓存 **≥ 2 小时**（或会话级），过期后前端提示重新构建。

## 六、验收清单

- [ ] 模型列表至少含 `maml`、`prototypical`；非法 `model_id` 有明确错误  
- [ ] `episodes:build` 强制 `model_id`，返回非空 `build_id` 与 `episodes`  
- [ ] `relations:infer` 在传入 `build_id` 时校验与 `model_id` 一致  
- [ ] 预测结果含 `h/r/t/score`，`r` 等于请求 `relation`  
- [ ] 与 `/api/v1/few-shot/*` 路径无冲突，可同时部署  
- [ ] 提供至少 1 组可用 curl 样例（含 token）方便前端联调
