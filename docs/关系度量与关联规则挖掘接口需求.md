# 关系度量与排序 / 结果导出 / 关联规则挖掘 · 算法接口需求

> **用途**：供算法侧按契约实现 HTTP 接口。前端为审计目录专用页，当前本地 Mock，联调时替换为真实请求。  
> **前端组件**：  
> - `RelationMeasureRanking.tsx`（`relation-measure-ranking`）——关系度量与排序 + 关系分析结果导出（同页）  
> - `AssociationRuleMining.tsx`（`association-rule-mining`）——关联规则挖掘  
> **建议 Base**：`http://127.0.0.1:18210`（可与多模态 `18200` / 规则学习 `18190` 分端口，或挂同一网关 `/api/v1`）

统一响应：

```json
{"status":"ok","data":{},"error":null}
```

失败时 `status=error`，`error` 为原因字符串，HTTP `400/404/500`。字段默认 **snake_case**。

异步任务统一返回 `job_id`，用 `GET /api/v1/jobs/{job_id}` 查询进度（关联规则挖掘必选；路径发现可选）。

## 功能点对照

| 模块 | 功能点 | 接口 | 说明 |
| --- | --- | --- | --- |
| 关系度量与排序 | 多步路径发现 | `POST /api/v1/relation-measure/paths:discover` | 两实体间指定深度内全部路径 |
| 关系度量与排序 | 路径评分批量计算 | `POST /api/v1/relation-measure/paths:score` | 按评分模型对路径批量打分 |
| 关系度量与排序 | 结果排序与筛选 | `POST /api/v1/relation-measure/paths:filter` | 按评分/长度/节点关系筛选排序 |
| 关系分析结果导出 | 导出为表格数据 | `POST /api/v1/relation-measure/export:table` | CSV / Excel |
| 关系分析结果导出 | 导出为可视化图片 | `POST /api/v1/relation-measure/export:image` | PNG / SVG（或返回图数据由前端渲染） |
| 关联规则挖掘 | 数据子集选择 | `GET /api/v1/assoc-rules/subsets` | 可选子集清单与规模 |
| 关联规则挖掘 | 算法参数配置 | `GET /api/v1/assoc-rules/algorithms` | 算法与参数约束（校验用） |
| 关联规则挖掘 | 规则挖掘任务执行 | `POST /api/v1/assoc-rules/jobs` · `GET .../jobs/{id}` · `GET .../jobs/{id}/rules` | 后台异步挖掘 |
| 公共 | 能力清单 | `GET /api/v1/relation-measure/capabilities` · `GET /api/v1/assoc-rules/capabilities` | 可选 |

**公共路径对象 `path`**（后文复用）：

```json
{
  "path_id": "p1",
  "length": 2,
  "hops": [
    {"from": "知识图谱", "from_id": "e_kg", "relation": "应用于", "relation_id": "r_apply", "to": "自然语言处理", "to_id": "e_nlp"},
    {"from": "自然语言处理", "from_id": "e_nlp", "relation": "引用", "relation_id": "r_cite", "to": "Transformer", "to_id": "e_tf"}
  ],
  "score": null,
  "model_scores": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| path_id | string | 路径唯一 ID（同一次 discover 内唯一） |
| length | int | 跳数（= hops 条数） |
| hops | object[] | 有序边列表 |
| hops[].from / to | string | 实体展示名 |
| hops[].from_id / to_id | string | 图谱实体 ID（推荐必填，便于去重与导出） |
| hops[].relation | string | 关系类型名 |
| hops[].relation_id | string \| null | 关系类型 ID |
| score | float \| null | 当前选用模型下的综合得分；未打分时为 `null` |
| model_scores | object | 可选：各模型得分缓存，键为 `scoring_model` |

实体标识：请求可用 `entity_id` 或 `entity_name`；若两者都传，以 `entity_id` 为准。

## 一、关系度量与排序

### 1. 多步路径发现

**功能点**：提供高效的图算法，用于发现两个实体之间指定深度内的所有连接路径。

`POST /api/v1/relation-measure/paths:discover`

#### 1.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| source_entity_id | string | 二选一 | 源实体 ID |
| source_entity_name | string | 二选一 | 源实体名称（模糊匹配时需返回实际命中 ID） |
| target_entity_id | string | 二选一 | 目标实体 ID |
| target_entity_name | string | 二选一 | 目标实体名称 |
| max_depth | int | 是 | 最大跳数，建议范围 `[1, 6]`，默认 `3` |
| graph_id | string | 否 | 图谱/分区 ID，默认当前业务图 |
| directed | bool | 否 | 是否按有向边搜索，默认 `true` |
| allow_relation_types | string[] | 否 | 仅允许的关系类型（名或 ID） |
| deny_relation_types | string[] | 否 | 排除的关系类型 |
| max_paths | int | 否 | 最多返回路径数，默认 `200`，超出时截断并在 `truncated` 中说明 |
| algorithm | string | 否 | `bfs` \| `dfs` \| `yen` 等，默认 `bfs` |

```json
{
  "source_entity_name": "知识图谱",
  "target_entity_name": "Transformer",
  "max_depth": 3,
  "directed": true,
  "max_paths": 200
}
```

#### 1.2 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| request_id | string | 请求追踪 ID |
| source | object | `{ "entity_id", "entity_name" }` 实际命中 |
| target | object | 同上 |
| max_depth | int | 实际使用的深度 |
| path_count | int | 返回路径条数 |
| truncated | bool | 是否因 `max_paths` 截断 |
| paths | object[] | 路径列表（`score` 一般为 `null`） |
| elapsed_ms | int | 可选，耗时 |

```json
{
  "status": "ok",
  "data": {
    "request_id": "req_path_001",
    "source": {"entity_id": "e_kg", "entity_name": "知识图谱"},
    "target": {"entity_id": "e_tf", "entity_name": "Transformer"},
    "max_depth": 3,
    "path_count": 6,
    "truncated": false,
    "paths": [
      {
        "path_id": "p1",
        "length": 2,
        "hops": [
          {"from": "知识图谱", "from_id": "e_kg", "relation": "应用于", "relation_id": "r_apply", "to": "自然语言处理", "to_id": "e_nlp"},
          {"from": "自然语言处理", "from_id": "e_nlp", "relation": "引用", "relation_id": "r_cite", "to": "Transformer", "to_id": "e_tf"}
        ],
        "score": null,
        "model_scores": {}
      }
    ],
    "elapsed_ms": 42
  },
  "error": null
}
```

#### 1.3 错误

- 源/目标实体不存在 → `400`，`entity_not_found`  
- `max_depth` 超范围 → `400`  
- 无路径 → `status=ok`，`path_count=0`，`paths=[]`（不要当错误）

### 2. 路径评分批量计算

**功能点**：根据用户选定的评分模型，对所有发现的路径进行自动化的批量打分。

`POST /api/v1/relation-measure/paths:score`

#### 2.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| scoring_model | string | 是 | 评分模型 ID，见下表 |
| paths | object[] | 条件 | 待打分路径；与 `discover_request_id` 二选一 |
| discover_request_id | string | 条件 | 复用上次 discover 缓存的路径集合 |
| relation_weights | object | 否 | 关系类型 → 权重，默认各边 `1.0`；用于 `rel_product` / `path_len` |
| model_params | object | 否 | 模型扩展参数（如 `gamma` 衰减系数） |

内置 `scoring_model`（与前端 Mock 对齐，可扩展）：

| ID | 名称 | 计算说明（建议） |
| --- | --- | --- |
| `path_len` | 路径长度衰减 | `score = ∏(w_i) / length` 或指数衰减 |
| `rel_product` | 关系权重乘积 | `score = ∏(w_i)` |
| `reliability` | 路径可靠性 | 边证据/置信度加权几何平均 |

```json
{
  "scoring_model": "path_len",
  "paths": [
    {
      "path_id": "p1",
      "length": 2,
      "hops": [
        {"from_id": "e_kg", "relation_id": "r_apply", "to_id": "e_nlp"},
        {"from_id": "e_nlp", "relation_id": "r_cite", "to_id": "e_tf"}
      ]
    }
  ],
  "relation_weights": {"应用于": 0.9, "引用": 0.95}
}
```

#### 2.2 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| request_id | string | 本次评分请求 ID |
| scoring_model | string | 实际使用的模型 |
| path_count | int | 打分条数 |
| paths | object[] | 回填 `score`；建议同时写入 `model_scores[scoring_model]` |
| score_stats | object | 可选：`min` / `max` / `mean` |

```json
{
  "status": "ok",
  "data": {
    "request_id": "req_score_001",
    "scoring_model": "path_len",
    "path_count": 1,
    "paths": [
      {
        "path_id": "p1",
        "length": 2,
        "hops": [],
        "score": 0.91,
        "model_scores": {"path_len": 0.91}
      }
    ],
    "score_stats": {"min": 0.91, "max": 0.91, "mean": 0.91}
  },
  "error": null
}
```

`hops` 可原样回传或省略（前端已有）；若省略，必须保留 `path_id` 与 `score` 对应。

#### 2.3 错误

- 未知 `scoring_model` → `400`  
- `paths` 与 `discover_request_id` 皆空 / 缓存失效 → `400`

### 3. 结果排序与筛选

**功能点**：支持用户根据综合评分、路径长度、包含/排除特定节点或关系等条件，对路径结果进行排序和筛选。

`POST /api/v1/relation-measure/paths:filter`

> 也可由前端纯本地筛选；提供本接口便于大数据量时服务端分页，以及导出前统一快照。

#### 3.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| paths | object[] | 条件 | 已打分路径列表 |
| score_request_id | string | 条件 | 复用上次 score 结果 |
| sort_by | string | 否 | `score` \| `length`，默认 `score` |
| sort_order | string | 否 | `desc` \| `asc`；`score` 默认 `desc`，`length` 默认 `asc` |
| min_score | float | 否 | 最低综合评分，默认 `0` |
| max_length | int | 否 | 最大路径长度 |
| include_node | string | 否 | 路径必须包含的节点名或 ID（子串匹配名 / 精确匹配 ID） |
| exclude_node | string | 否 | 路径不得包含的节点 |
| include_relation | string | 否 | 必须包含的关系 |
| exclude_relation | string | 否 | 不得包含的关系 |
| page | int | 否 | 从 1 开始，默认 1 |
| page_size | int | 否 | 默认 `50`，最大 `500` |

```json
{
  "score_request_id": "req_score_001",
  "sort_by": "score",
  "sort_order": "desc",
  "min_score": 0.6,
  "max_length": 4,
  "include_node": "BERT",
  "exclude_relation": "隶属于",
  "page": 1,
  "page_size": 50
}
```

#### 3.2 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| request_id | string | 筛选请求 ID（导出可引用） |
| total | int | 筛选后总条数 |
| page | int | 当前页 |
| page_size | int | 页大小 |
| paths | object[] | 当前页路径（含 `score`） |
| applied_filters | object | 回显实际生效的筛选条件 |

## 二、关系分析结果导出

与度量页共用路径结果；导出可基于 `filter_request_id` / `score_request_id` / 显式 `paths`。

### 4. 导出为表格数据

**功能点**：将发现的路径列表及其评分以 CSV 或 Excel 格式导出。

`POST /api/v1/relation-measure/export:table`

#### 4.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| format | string | 是 | `csv` \| `xlsx`（`xls` 可用 `xlsx` 兼容） |
| paths | object[] | 条件 | 导出路径 |
| filter_request_id | string | 条件 | 导出筛选快照 |
| score_request_id | string | 条件 | 导出打分快照 |
| columns | string[] | 否 | 默认 `["path_id","length","score","path"]` |
| filename_prefix | string | 否 | 文件名前缀，默认 `relation-paths` |

`path` 列建议序列化为：`实体A -[关系]-> 实体B -[关系]-> 实体C`。

#### 4.2 出参

**推荐 A**：直接返回文件流  

- `Content-Type`: `text/csv; charset=utf-8` 或 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`  
- `Content-Disposition: attachment; filename="relation-paths-xxx.csv"`  
- 成功时 HTTP 200，body 为文件；失败时仍可用 JSON `{status,error}`。

**推荐 B**：JSON 包装（便于网关统一）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| format | string | `csv` \| `xlsx` |
| filename | string | 建议下载名 |
| mime | string | MIME |
| content_base64 | string | 文件内容 base64 |
| row_count | int | 行数（不含表头） |

```json
{
  "status": "ok",
  "data": {
    "format": "csv",
    "filename": "relation-paths-知识图谱-Transformer.csv",
    "mime": "text/csv;charset=utf-8",
    "content_base64": "cGF0aF9pZCxsZW5ndGgsc2NvcmUscGF0aAouLi4=",
    "row_count": 6
  },
  "error": null
}
```

**功能点**：将当前关系分析可视化网络图导出为 PNG 或 SVG。

| format | string | 是 | `png` \| `svg` |
| paths | object[] | 条件 | 用于构图的路径（建议筛后结果） |

```json
{
  "format": "png",
  "filter_request_id": "req_filter_001",
  "layout": "force",
  "width": 1120,
  "height": 560
}
```

#### 5.2 出参

同 §4：**文件流** 或 **JSON + content_base64**。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| format | string | `png` \| `svg` |
| filename | string | 如 `relation-network-xxx.png` |
| mime | string | `image/png` / `image/svg+xml` |
| content_base64 | string | 图片内容 |

## 三、关联规则挖掘

### 6. 数据子集选择

**功能点**：允许用户选择知识图谱的特定部分作为挖掘的数据源。

`GET /api/v1/assoc-rules/subsets`

#### 6.1 入参（Query）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| graph_id | string | 否 | 图谱 ID |

#### 6.2 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| subsets | object[] | 可选子集列表 |

`subsets[]`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| subset_id | string | 如 `sci` / `bio` / `mat` / `full` |
| name | string | 展示名，如「科技领域子图」 |
| description | string | 实体类型、关系范围说明 |
| entity_count | int | 实体规模 |
| triple_count | int | 三元组/事务规模 |
| entity_types | string[] | 可选 |
| relation_types | string[] | 可选 |
| recommended_min_support | float | 可选推荐支持度下界 |

```json
{
  "status": "ok",
  "data": {
    "subsets": [
      {
        "subset_id": "sci",
        "name": "科技领域子图",
        "description": "实体类型：技术 / 概念 / 组织；关系：应用于、引用、研究",
        "entity_count": 124000,
        "triple_count": 862000,
        "entity_types": ["技术", "概念", "组织"],
        "relation_types": ["应用于", "引用", "研究"],
        "recommended_min_support": 0.05
      }
    ]
  },
  "error": null
}
```

`POST /api/v1/assoc-rules/subsets:resolve`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| entity_type_filter | string[] | 否 | 实体类型白名单 |
| relation_type_filter | string[] | 否 | 关系类型白名单 |
| seed_entity_ids | string[] | 否 | 以种子实体 k-hop 扩张 |
| hop | int | 否 | 扩张跳数，默认 `2` |

返回临时 `subset_id`（会话级）及规模估计，供任务提交使用。

### 7. 算法参数配置

**功能点**：配置挖掘算法核心参数（最小支持度、最小置信度等）。本接口提供**可选项与合法范围**；真正执行在 §8。

`GET /api/v1/assoc-rules/algorithms`

#### 7.1 出参 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| algorithms | object[] | 可用算法 |

`algorithms[]`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| algorithm_id | string | `apriori` \| `fpgrowth` |
| name | string | 展示名 |
| description | string | 适用场景 |
| params | object[] | 可配参数 schema |

`params[]`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 如 `min_support` |
| type | string | `float` \| `int` |
| required | bool | |
| default | number | |
| min / max | number | 合法区间 |
| description | string | |

```json
{
  "status": "ok",
  "data": {
    "algorithms": [
      {
        "algorithm_id": "apriori",
        "name": "Apriori",
        "description": "经典频繁项集挖掘，适合中小规模子集",
        "params": [
          {"name": "min_support", "type": "float", "required": true, "default": 0.05, "min": 0.01, "max": 0.5, "description": "最小支持度"},
          {"name": "min_confidence", "type": "float", "required": true, "default": 0.6, "min": 0.3, "max": 0.99, "description": "最小置信度"},
          {"name": "max_itemset_size", "type": "int", "required": false, "default": 3, "min": 2, "max": 8, "description": "最大项集长度"}
        ]
      },
      {
        "algorithm_id": "fpgrowth",
        "name": "FP-Growth",
        "description": "压缩树结构，适合大规模图事务",
        "params": [
          {"name": "min_support", "type": "float", "required": true, "default": 0.03, "min": 0.01, "max": 0.5, "description": "最小支持度"},
          {"name": "min_confidence", "type": "float", "required": true, "default": 0.7, "min": 0.3, "max": 0.99, "description": "最小置信度"},
          {"name": "max_itemset_size", "type": "int", "required": false, "default": 3, "min": 2, "max": 8, "description": "最大项集长度"}
        ]
      }
    ]
  },
  "error": null
}
```

可选校验接口（提交任务前调用）：

`POST /api/v1/assoc-rules/params:validate`

入参：`subset_id` + `algorithm_id` + 参数字典；出参：`valid: bool`、`errors: string[]`、`warnings: string[]`（如全库 + 过低 support 的告警）。

### 8. 规则挖掘任务执行

**功能点**：后台任务管理，支持执行耗时较长的关联规则挖掘任务。

#### 8.1 提交任务

`POST /api/v1/assoc-rules/jobs`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| subset_id | string | 是 | §6 返回的子集 ID |
| algorithm_id | string | 是 | `apriori` \| `fpgrowth` |

## 五、联调验收清单（算法自测）

1. **路径发现**：`知识图谱` → `Transformer`，`max_depth=3` 返回多条路径；`max_depth=1` 条数不应多于深度 3；实体不存在返回明确错误。  
2. **批量评分**：同一组路径换 `path_len` / `rel_product`，`score` 应变化；`score ∈ [0,1]`（或文档声明其他区间）。  
3. **筛选**：`min_score` 提高后 `total` 下降；`include_node` / `exclude_relation` 生效。  
4. **表格导出**：CSV 可用 Excel 打开，含表头与评分列；行数 = 导出路径数。  
5. **图片导出**（若实现）：PNG/SVG 非空，图中含源/目标节点。  
6. **关联规则**：选子集 → 提交 job → 轮询至 `done` → `/rules` 非空；`confidence >= min_confidence`；非法参数被 `validate` 或提交时拒绝。
