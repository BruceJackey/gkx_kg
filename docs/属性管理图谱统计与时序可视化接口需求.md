# 属性管理：图谱统计与时序可视化接口需求

> 前端页面：`PropertyManagement.tsx` 中「图谱统计」「时序可视化」两个子 Tab。  
> 用途：供算法同学基于 TRS 图谱读取数值型属性，计算分布/离群与时序突变，供前端直接替换本地 Mock。  
> 联调数据优先使用已写入的原型图 `prototype_enterprise_graph` / `prototype_science_topic_graph`，批次 `prototype_seed_20260828`。

---

## 1. 页面要展示什么

### 1.1 图谱统计（`stats`）

对**某一图谱空间中某一实体类型上的某一数值型属性**，做全体样本统计：

| UI 区块 | 前端当前 Mock | 需要算法返回 |
|---|---|---|
| 分析属性选择器 | H指数 / 员工人数 | 可分析属性目录 |
| 值分布直方图 | 分箱计数，离群 bin 高亮 | `bins[]` |
| 箱线图 | Min / Q1 / 中位数 / Q3 / Max / 须线 | `boxPlot` |
| 摘要卡 | 均值、IQR、离群点数 | `summary` |
| 离群点下钻 | 列出超限实体 | `outliers[]` |

当前前端用写死的 `H_VALUES` 本地算 IQR；接入后这些计算全部由算法完成，前端只渲染。

### 1.2 时序可视化（`timeseries`）

对**某一图谱空间中某一个实体的某一个数值型属性**，按时间拉出序列并检测突变：

| UI 区块 | 前端当前 Mock | 需要算法返回 |
|---|---|---|
| 实体 + 属性选择 | 李明·论文数 / 研究院·员工数 | 实体与可时序属性目录 |
| 折线图 | `date / value / anomaly` | `points[]` |
| 均值参考线 | 本地 mean | `summary.mean` |
| 异常点列表 | `anomaly=true` 的点 | `anomalies[]` |
| 异常详情文案 | “相对滚动均值 > 2.5σ” | `reason` + 检测参数 |

用户明确约束：**算法输入是「TRS 某个图谱 + 某个实体 + 某个数值型属性」**，然后跑时序与异常检测。图谱统计则是「TRS 某个图谱 + 某个实体类型/Tag + 某个数值型属性」的横向分布分析。

## 2. 可用联调图与时序造数

### 2.1 TRS 地址（与垂直领域一致）

| 项 | 值 |
|---|---|
| Gateway | `http://114.117.127.200:7001` |
| Space（企业） | `prototype_enterprise_graph` |
| Space（科研专题） | `prototype_science_topic_graph` |
| 数据批次 | `prototype_seed_20260828` |

凭据用环境变量，不进仓库。

### 2.2 强烈推荐的时序数据路径（企业图）

造数脚本 `scripts/seed_prototype_data.py` + 构图脚本 `scripts/build_trs_test_graphs.py` 已把企业年度财务做成时序：

```text
企业(VID=PROTO_ORG_*)
  --具有快照(year)--> 属性快照(VID=SNAPSHOT::{orgId}::{year})
```

`属性快照` Tag 数值属性：

| 属性 | 类型 | 含义 | 页面用途 |
|---|---|---|---|
| `operating_revenue` | double | 营业收入（原始金额） | 时序主指标 |
| `pure_profit` | double | 净利润 | 时序备选 |
| `rd_amount` | double | 研发投入 | 时序备选 |
| `employees` | int | 员工人数 | 时序备选 / 分布统计 |
| `total_assets` | double | 总资产 | 时序备选 |
| `total_liabilities` | double | 总负债 | 时序备选 |
| `year` | int | 年份 | 时间轴 |

每个核心企业约有 **2021–2025 共 5 个年度点**，且营收按年约 +16% 增长，员工逐年增加，适合画折线并做突变检测。

验收锚点示例：

| entityId | 名称 | 建议属性 |
|---|---|---|
| `PROTO_ORG_MED001` | 华研精准医疗科技有限公司 | `operating_revenue` / `rd_amount` / `employees` |
| `PROTO_ORG_CHEM001` | 粤科先进材料有限公司 | 同上 |
| `PROTO_ORG_OCEAN001` | 蓝海智能装备有限公司 | 同上 |
| `PROTO_ORG_QUANT001` | 量芯计算科技有限公司 | 同上 |

查询示意（算法侧实现，不必原样照抄）：

```ngql
USE `prototype_enterprise_graph`;
GO FROM "PROTO_ORG_MED001" OVER `具有快照`
YIELD dst(edge) AS snapshot_vid, properties(edge).year AS year;
FETCH PROP ON `属性快照` "SNAPSHOT::PROTO_ORG_MED001::2021", ...
YIELD properties(vertex).operating_revenue, properties(vertex).year;
```

金额展示建议：接口可返回原始值与换算后的亿元值；前端时序图优先用亿元字段，避免量级过大。

### 2.3 可用于图谱统计的分布样本

| 图空间 | Tag | 数值属性 | 样本来源 |
|---|---|---|---|
| `prototype_enterprise_graph` | `属性快照` | `operating_revenue` 等 | 全部企业某一年快照，或最新一年 |
| `prototype_enterprise_graph` | `企业` | `registered_capital` | 企业顶点本身 |
| `prototype_science_topic_graph` | `学者` | `h_index`、`citation_count` | 与页面 Mock「H指数」最接近 |
| `prototype_science_topic_graph` | `论文` | `download_count` | 备选分布 |

说明：页面 Mock 写的是「人物 H指数」；原型企业图没有把 H 指数挂在企业上，科研专题图的 `学者.h_index` 才是对口字段。联调时请把属性目录按真实 Tag Schema 返回，不要硬编码页面旧 Mock 名称。

### 2.4 其他带时间语义、但本接口不做主路径的数据

| 数据 | TRS 形态 | 备注 |
|---|---|---|
| 行业演变 | 企业 →`属于行业`→ 行业分类（含 year） | 分类属性，非连续数值时序 |
| 企业新闻 | 企业 →`发生`→ 事件 | 事件序列，可做辅证，不作为本接口主数值序列 |
| 专利公开年 | 专利.year | 适合计数聚合，不适合单实体连续财务曲线 |

算法侧**不限定图谱、实体类型和属性名称**：`graphSpace/tag/entityId/attribute`
均由调用方传入。算法服务只做安全校验、TRS Schema 数值类型校验和确定性计算；
`timeseriesVia=null` 时调用方必须补齐 `entityType/snapshotTag/edgeType/timeField`。

前端接入约定：

- 属性选项用 `entityType::tag::attribute` 作为唯一键；
- 时序面板仅展示带完整 `timeseriesVia` 的属性，并把路径一并传给 entities/timeseries；
- 分布面板支持 `vertex` 与 `snapshot` 两种 source，snapshot 请求带 `entityType`。

### 2.5 故意植入的异常点（演示用）

为让时序突变检测可演示，造数在平滑增长基础上加入两处可被默认规则
`rolling_zscore(window=4, zThreshold=2.5)` 检出的突变：

| 实体 | 年份 | 属性 | 变化 |
|---|---|---|---|
| `PROTO_ORG_MED001` 华研精准医疗 | 2023 | `operating_revenue` / `rd_amount` | 相对趋势约抬升 3.2 倍 |
| `PROTO_ORG_QUANT001` 量芯计算科技 | 2024 | `employees` | 相对趋势约腰斩至 35% |

其余企业、其余年份仍保持平滑增长，用于对照“无异常”场景。

## 3. 公共约定

### 3.1 HTTP

与现有算法网关一致，建议挂到：

```text
/api/v1/property-analytics/...
```

鉴权：

```http
Authorization: Bearer <GATEWAY_API_TOKEN>
```

统一 envelope：

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_xxx",
  "data": {}
}
```

错误：

| HTTP | code | 场景 |
|---:|---|---|
| 400 | `INVALID_ARGUMENT` | space/属性/时间粒度非法 |
| 404 | `NOT_FOUND` | 图空间、实体、属性不存在 |
| 422 | `UNSUPPORTED_ATTRIBUTE` | 属性非数值型或不可统计/不可时序 |
| 500 | `INTERNAL_ERROR` | TRS/内部异常（不回传凭据） |

### 3.2 输入语义

| 字段 | 含义 |
|---|---|
| `graphSpace` | TRS space 名，如 `prototype_enterprise_graph` |
| `entityType` / `tag` | Nebula Tag，如 `企业`、`学者`、`属性快照` |
| `entityId` | 顶点 VID，如 `PROTO_ORG_MED001` |
| `attribute` | 数值属性名，如 `operating_revenue`、`h_index`、`employees` |
| `asOf` | 可选，`YYYY-MM-DD`，统计/序列截止时间 |

数值属性白名单建议由服务根据 Tag Schema 动态发现，至少支持：

- 企业图：`operating_revenue,pure_profit,rd_amount,employees,total_assets,total_liabilities,registered_capital`
- 科研图：`h_index,citation_count,download_count`

## 4.2 图谱统计：属性值分布与离群

```http
POST /api/v1/property-analytics/distribution
Content-Type: application/json
```

请求：

```json
{
  "graphSpace": "prototype_enterprise_graph",
  "entityType": "企业",
  "attribute": "operating_revenue",
  "source": {
    "mode": "snapshot",
    "snapshotTag": "属性快照",
    "edgeType": "具有快照",
    "timeField": "year",
    "timeValue": 2025
  },
  "binCount": 7,
  "outlierMethod": "iqr",
  "iqrMultiplier": 1.5,
  "asOf": "2026-08-31",
  "limit": 5000
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `graphSpace` | 是 | TRS space |
| `entityType` | 是 | 统计主体类型；快照模式下指“归属企业/学者”等 |
| `attribute` | 是 | 数值属性 |
| `source.mode` | 是 | `vertex`=直接读实体属性；`snapshot`=经快照边读年度属性 |
| `source.timeValue` | 条件 | snapshot 模式必填年份/期次 |
| `binCount` | 否 | 默认 7，范围 3～30 |
| `outlierMethod` | 否 | 默认 `iqr`；可扩展 `zscore` |
| `iqrMultiplier` | 否 | 默认 1.5 |
| `limit` | 否 | 最大样本数，防止全图扫描过大 |

响应：


## 5. 算法要求

### 5.1 数据读取

1. 只读 TRS；不要为了页面再造一套与图不一致的假序列。
2. `asOf` 之后的快照/年份不得进入样本。
3. 悬空边、缺属性点跳过，并计入 `warnings` 或内部日志。
4. `meta.dataSources` 必须真实反映来源；读到 TRS 时写 `["trs"]`，降级契约样例时写 `["contract-fixture"]` 并给出 `warnings`。

### 5.2 分布与离群

1. 默认 IQR 规则与页面一致：`v < Q1 - 1.5*IQR` 或 `v > Q3 + 1.5*IQR`。
2. 箱线图须线使用 Tukey 风格：`max(min, Q1-1.5IQR)` / `min(max, Q3+1.5IQR)`。
3. 直方图分箱左闭右开，最后一箱右闭。
4. 离群列表必须带回 `entityId/entityName/value/reason`，供下钻。

### 5.3 时序突变

1. 默认实现与当前前端 Mock 对齐：对点 `i`，用前 `window` 个历史点算均值和标准差，`|v - mean| > zThreshold * std` 标为异常；历史不足 `minHistory` 时不判异常。
2. 允许后续换模型，但必须通过 `method` 回传，并保持 `points/anomalies` 字段兼容。
3. 不得因为“看起来增长很快”就人工加点；原型财务本身是平滑增长，**正常结果可以是 0 个异常点**。若要演示异常，应在测试数据中构造突变，或提供 `demoInject` 仅用于联调且默认关闭。

### 5.4 单位

- 财务金额：TRS 存原始货币金额；接口按请求 `unit` 转换。
- 员工人数、H 指数：不缩放。
- 响应中同时给 `value`（展示单位）与可选 `rawValue`（原始单位），避免前端二次换算误差。
