## 0. 筛选标准（何为「接口演示页」）

同时满足越多项越应纳入：

1. 独立 `pageId` / 独立组件，常从审计目录跳转；  
2. 主交互是「输入 → 调用 → 输出」或极简列表决策；  
3. 本地 Mock / `setTimeout`，文案含「调用…API / 接口演示 / 测试调用」；  
4. **不是**多 Tab 业务管理工作台、完整审核队列、数据源/本体/映射配置等产品页。

## 2. 统一约定

| 项 | 约定 |
|---|---|
| Base | `http(s)://{host}:{port}/api/v1`（多模态定位类可挂 `/mmkg` 前缀，见 §4） |
| 字段 | JSON **camelCase**（页面内部若展示 snake_case，由网关/前端映射，算法契约以 camelCase 为准） |
| 编码 | UTF-8 |
| 时间 | ISO 8601 UTC |
| 分数 | `[0,1]` 小数 |
| 文本偏移 | JS UTF-16 code unit，半开区间 `[start,end)` |
| 图像框 | 百分比 `x,y,w,h ∈ [0,100]`，左上角原点 |
| 无结果 | HTTP 200 + 空数组 |
| 鉴权 | `Authorization: Bearer <token>` + `X-Request-Id`；写操作加 `Idempotency-Key` |

统一成功响应：

```json
{ "code": "OK", "message": "success", "requestId": "req_xxx", "data": {} }
```

错误：`INVALID_ARGUMENT` / `NOT_FOUND` / `INTERNAL_ERROR`。

推理类结果必须含 `modelName`、`modelVersion`（可用 stub 名，不可省略）。

### 6.1 多维度文献解析

`POST /api/v1/literature/multidim:parse`

请求：`{ "fileName": "...", "objectKey"|"url"|"base64": ... }`  
响应：按页面区块返回结构化字段（章节/图表/公式/元数据等）。可用页面 `SAMPLE_LITERATURE` + `MOCK_RESULT` 作 stub 形状参考（见组件内常量）。

### 6.2 专利技术要素解构

`POST /api/v1/patent/technical-elements:parse`

请求：`{ "fileName": "一种基于图注意力的知识抽取方法及装置.pdf" }`  

响应 data（与页面四框一一对应）：

```json
{
  "claimsText": "权利要求1（独立权利要求）\n...",
  "matrixText": "技术特征\t技术功效\t关联强度\n...",
  "annotationText": "化学分子式：...\n...",
  "modulesText": "模块M1：...\n..."
}
```

测试文件名：页面 `SAMPLE_PATENTS` 三个 pdf 名。

### 6.3 多格式文献解析

`POST /api/v1/literature/formats:parse`

```json
{ "format": "pdf"|"jats"|"html", "content": "...或 objectKey" }
```

返回：标题、作者、摘要、章节树、引用等（按 format 分支）。

### 6.4 多模态内容识别与转写

`POST /api/v1/mmkg/content:transcribe`（同步演示）或异步 `POST /api/v1/mmkg/transcription-jobs`

输入图像/表格截图，输出：OCR 文本、表格结构、公式 LaTeX、图注文中索引。

### 6.5 大语言模型语义提炼

`POST /api/v1/nlp/semantic:refine`

默认样例文本（页面）：知识图谱补全 / TransE / RotatE / 低资源长尾关系相关段落。

```json
{ "text": "...", "tasks": ["paragraphSummary", "relationRefine"] }
```

返回：`paragraphSummary`、`relations[{ head, relation, tail, score }]`。

### 6.6 科研核心元组抽取

`POST /api/v1/science/core-tuples:extract`

```json
{ "text": "...", "schema": ["method", "material", "metric", "mechanism"] }
```

返回：`tuples[]` 标准化科研核心元组。

### 6.7 文本高亮种子标注

`POST /api/v1/annotation/seed-highlights:extract`

输入长文本，返回建议高亮 span 列表 `{ text, start, end, label, score }`，作为种子实例。

### 6.8 属性精确抽取 / 映射转换函数

- `POST /api/v1/entities/attributes:precise-extract`：`{ graphSpace, entityId }` → 精确属性 KV。  
- `POST /api/v1/mapping/transforms:apply`：`{ functionId, inputValue, params }` → `{ outputValue, logs[] }`。

### 6.9 局部学习标注器（一页三接口）

| Tab | 接口 | 入参要点 | 出参要点 |
|---|---|---|---|
| 局部学习标注 | `POST /api/v1/annotation/local-learning:bootstrap` | 文档 id/文本 + 种子标注 | 扩展标注结果文本/结构化 spans |
| 事件识别 API | `POST /api/v1/events:recognize` | `text` | 事件触发词、论元、类型 |
| 标注优化 API | `POST /api/v1/annotation/sentences:select` | 候选句子池 | 优选句子排序 + 理由 |

页面样例文档/事件文本见组件 `SAMPLE_ANNOTATION_DOCS`、`SAMPLE_EVENT_TEXTS`。

### 6.10 上层智能工具

- `POST /api/v1/tools/analogy:search`：图谱类比查询 → 答案 + 路径解释  
- `POST /api/v1/tools/research-questions:generate`：主题/文献 → 科研问题列表  

### 6.11 时序关系审计页

复用算法能力（亦在算法详情 Demo）：

- `POST /api/v1/temporal/relations:extract`：文本 → 时序关系三元组  
- `POST /api/v1/temporal/relations:analyze`：事件集合 → 依赖图/顺序约束

## 7. B3：匹配 / 链接 / 跨语言 / 消歧 / 写入 / LLM

### 7.1 文本实例匹配

`POST /api/v1/matching/text:compare`

```json
{ "left": "清华大学", "right": "Tsinghua University", "methods": ["string", "vector"] }
```

返回：`{ stringScore, vectorScore, fusedScore }`。  
测试对：`(清华大学,Tsinghua University)`、`(北京大学,Peking University)`、`(腾讯,Alibaba Group)`、`(中科院自动化研究所,Institute of Automation, CAS)`。

### 7.2 结构实例匹配 / 特征工程

- `POST /api/v1/matching/structure:compare`：`{ graphSpace, leftEntityId, rightEntityId }` → 邻居重叠、路径相似度等。  
- `POST /api/v1/matching/features:extract`：`{ left, right, leftAttrs, rightAttrs }` → 多维特征向量 + 解释。

### 7.3 候选实体生成 / 链接判断

- `POST /api/v1/linking/candidates:generate`：`{ mention, context, topK }` → `candidates[{ entityId, name, score, evidence }]`  
- `POST /api/v1/linking/judgment:score`：`{ mention, context, candidates[] }` → 每候选 `linkScore` + 建议 `bestId`

### 7.4 跨语言系列

| 接口 | 入参 | 出参 |
|---|---|---|
| `POST /api/v1/xling/instances:match` | `{ zh, en }` | 匹配分、对齐证据 |
| `POST /api/v1/xling/query:fuse` | `{ query, sourceLang, targetKb }` | 翻译查询 + 融合候选 |
| `POST /api/v1/xling/attributes:align` | `{ leftAttrs, rightAttrs, langs }` | 属性名/值对齐表 |
| `POST /api/v1/xling/kb:align` | `{ sourceKb, targetKb, strategy }` | 对齐任务 id 或批量结果 |

跨语言实例匹配测试对见页面 `PAIR_EXAMPLES`。

### 7.5 实体匹配消歧

- `GET /api/v1/matching/disambiguation/candidates?status=pending`  
- `POST /api/v1/matching/disambiguation/candidates/{id}:decide` body `{ decision, chosenEntityId? }`  

### 7.6 已验证知识写入

`POST /api/v1/kg/verified-triples:write`

```json
{
  "triplesText": "<Geoffrey Hinton> <就职于> <多伦多大学>\n...",
  "graphSpace": "kg:sci-paper-v3",
  "validateOnly": false
}
```

返回：`acceptedCount/rejectedCount/errors[]`。页面默认 `SAMPLE_TRIPLES` 可作为测试输入。

### 7.7 多模型 API 集成（连通测试）

`POST /api/v1/llm/chat/completions`

```json
{
  "model": "gpt-4o",
  "messages": [{ "role": "user", "content": "ping" }],
  "maxTokens": 16
}
```

返回：`{ content, latencyMs, model }`。页面用于配置多模型并点「测试调用」。
