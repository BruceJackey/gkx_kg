# 异质多模态特征融合 / 强化学习框架 / 少样本三元组 · 算法接口需求

> **用途**：供算法侧按契约实现 HTTP 接口。前端页面对应审计目录专用页，当前为本地 Mock，联调时替换为真实请求。  
> **前端组件**：  
> - `HeterogeneousMultimodalFusion.tsx`（`heterogeneous-multimodal-fusion`）  
> - `RLFrameworkIntegration.tsx`（`rl-framework-integration`）  
> - `FewShotTripleGeneration.tsx`（`few-shot-triple-generation`）  
> **建议 Base**：`http://127.0.0.1:18200`（可与规则学习 `18190` 分端口，或挂同一网关 `/api/v1`）

统一响应：

```json
{"status":"ok","data":{},"error":null}
```

失败时 `status=error`，`error` 为原因字符串，HTTP `400/404/500`。字段默认 **snake_case**；若网关统一 camelCase，需在联调前约定映射表，算法实现以本文 snake_case 为准。

异步任务统一返回 `job_id`，可用 `GET /api/v1/jobs/{job_id}` 查询（可选实现，见文末）。

## 一、异质多模态特征融合

### 范围说明

- **本期算法接口仅覆盖「特征对齐与归一化」**：输入真实文本 + 图像，输出各模态原生向量、对齐后向量。  
- **早期融合 / 晚期融合**：前端架构图示 + 文案介绍，**不要求算法提供独立推理接口**（融合逻辑体现在下游模型内部）。若后续需要演示「对齐后拼接」，可复用本接口返回的 `aligned` 向量在前端做 Concat / 加权平均展示。

模态范围：**文本 + 图像**（不含图谱结构）。

---

### 1. 特征对齐与归一化

`POST /api/v1/mm-fusion/align:normalize`

对文本与图像分别编码，再按指定策略对齐到统一维度并归一化。

#### 1.1 Content-Type

推荐 **multipart/form-data**（含文件）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| text | string | 是 | 原始文本 |
| image | file | 是 | 图片文件（`image/jpeg` / `image/png` / `image/webp`） |
| target_dim | int | 否 | 对齐目标维度，默认 `768`，建议范围 `[8, 2048]` |
| align_mode | string | 否 | `pad` \| `truncate` \| `pca`，默认 `pad` |
| norm_mode | string | 否 | `l2` \| `minmax` \| `zscore` \| `none`，默认 `l2` |
| text_encoder | string | 否 | 文本编码器名，默认服务配置（如 `scibert` / `clip-text`） |
| image_encoder | string | 否 | 图像编码器名，默认（如 `clip-vision`） |

也支持 JSON（图像用 base64）：

```json
{
  "text": "知识图谱将实体与关系结构化表示…",
  "image_base64": "<纯 base64 或 dataURL>",
  "image_mime": "image/jpeg",
  "target_dim": 8,
  "align_mode": "pad",
  "norm_mode": "l2"
}
```

#### 1.2 输出 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| request_id | string | 请求追踪 ID |
| text_raw | object | 文本编码结果 |
| text_raw.dim | int | 原生维度 |
| text_raw.vector | float[] | 对齐前向量 |
| text_raw.encoder | string | 实际使用的编码器 |
| image_raw | object | 图像编码结果（结构同 `text_raw`） |
| aligned | object[] | 对齐+归一化后各模态 |
| aligned[].modality | string | `text` \| `image` |
| aligned[].before_dim | int | 对齐前维度 |
| aligned[].after_dim | int | 对齐后维度（= target_dim） |
| aligned[].vector | float[] | 处理后向量 |
| align_mode | string | 实际对齐方式 |
| norm_mode | string | 实际归一化方式 |
| target_dim | int | 目标维度 |

```json
{
  "status": "ok",
  "data": {
    "request_id": "req_mm_001",
    "text_raw": {
      "dim": 768,
      "vector": [0.12, -0.04],
      "encoder": "clip-text"
    },
    "image_raw": {
      "dim": 512,
      "vector": [0.33, 0.01],
      "encoder": "clip-vision"
    },
    "aligned": [
      {
        "modality": "text",
        "before_dim": 768,
        "after_dim": 512,
        "vector": [0.08, -0.02]
      },
      {
        "modality": "image",
        "before_dim": 512,
        "after_dim": 512,
        "vector": [0.11, 0.00]
      }
    ],
    "align_mode": "pca",
    "norm_mode": "l2",
    "target_dim": 512
  },
  "error": null
}
```

> 示例中 `vector` 可截断返回前 N 维并另附 `vector_preview_dim`；完整向量建议始终返回，便于联调（向量过大时可约定 `return_full_vector=false` 只回 preview）。

#### 1.3 错误

| 条件 | error 建议 |
| --- | --- |
| 缺 text / image | `missing_text` / `missing_image` |
| 不支持的图片类型 | `unsupported_image_type` |
| 非法 align_mode / norm_mode | `invalid_align_mode` / `invalid_norm_mode` |
| 编码失败 | `encode_failed` |

#### 1.4 curl 示例

```bash
curl -sS -X POST "$BASE/api/v1/mm-fusion/align:normalize" \
  -F 'text=知识图谱将实体与关系结构化表示' \
  -F 'image=@./sample.jpg' \
  -F 'target_dim=512' \
  -F 'align_mode=pca' \
  -F 'norm_mode=l2'
```

## 二、强化学习框架集成

将知识补全建模为路径搜索 MDP：智能体从查询头实体出发，选择出边，在有限跳数内到达正确尾实体。

建议任务态：`env` → `training job` → `metrics` 可按 `job_id` / `env_id` / `policy_id` 衔接。

---

### 2. RL 环境定义

`POST /api/v1/rl-kg/envs`

创建（或更新）RL 环境配置。

#### 2.1 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 否 | 环境名称 |
| state_desc | string | 是 | 状态定义说明（前端表单原文可存） |
| action_space | string | 是 | 动作空间说明，如「出边选择」 |
| max_hops | int | 是 | 最大跳数，建议 `[1, 8]` |
| reward_hit | float | 是 | 命中目标尾实体奖励 |
| reward_step | float | 是 | 每步代价（通常为负） |
| reward_fail | float | 是 | 失败/超时惩罚 |
| graph_space | string | 否 | 图谱空间 / TRS space |
| query_template | object | 否 | 默认查询形态，如 `{head, relation}` |
| env_id | string | 否 | 传入则更新已有环境 |

```json
{
  "name": "kg-completion-path-v1",
  "state_desc": "当前实体节点 + 已走过路径 + 查询 (h, r, ?)",
  "action_space": "出边选择（邻接关系 / 尾实体）",
  "max_hops": 3,
  "reward_hit": 1.0,
  "reward_step": -0.05,
  "reward_fail": -0.5,
  "graph_space": "scientific_kg"
}
```

#### 2.2 输出 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| env_id | string | 环境 ID |
| reward_formula | string | 服务端规范化公式摘要 |
| created_at | string | ISO8601 |
| status | string | `ready` \| `draft` |

### 3. 策略网络训练与管理

#### 3.1 启动训练

### 4. 训练过程监控

`GET /api/v1/rl-kg/trainings/{job_id}/metrics`

可选查询参数：`from_episode`、`to_episode`。

#### 4.1 输出 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| job_id | string | 训练任务 |
| status | string | `queued` \| `running` \| `succeeded` \| `failed` |
| policy | string | 策略类型 |
| current_episode | int | 当前已完成 episode |
| total_episodes | int | 总 episode |
| series | object[] | 时序点 |
| series[].episode | int | episode 序号（从 1） |
| series[].reward | float | 累计奖励（或 episode 回报，需在实现说明中固定一种；建议 **episode return 的滑动/累计均值**，字段名保持 `reward`） |
| series[].success_rate | float | `[0,1]` 成功率（命中目标尾实体比例） |
| latest | object | 最新一点的摘要，便于卡片展示 |

```json
{
  "status": "ok",
  "data": {
    "job_id": "tr_01",
    "status": "running",
    "policy": "ppo",
    "current_episode": 40,
    "total_episodes": 80,
    "series": [
      {"episode": 1, "reward": -1.2, "success_rate": 0.08},

      "episode": 40,
      "reward": 2.6,
      "success_rate": 0.55
    }
  },
  "error": null
}
```

前端用 `series` 绘制「累计奖励」「成功率」两条曲线。

## 三、少样本学习三元组生成

在数据稀疏或新关系场景下，用少量支持集样本生成/预测三元组。  
**实现建议**：支持集作为示例条件，对查询头实体做尾实体预测（可用原型网络 / 匹配网络 / 关系网络；亦可用上下文式推理实现，**对外接口与文案保持少样本/元学习表述，不暴露上下文学习字样**）。

---

### 5. 元学习任务构建

`POST /api/v1/few-shot/meta-tasks:build`

从知识库采样，构建 N-way K-shot 任务（每任务含 support / query）。

#### 5.1 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| n_way | int | 否 | 关系种类数，默认 `3` |
| k_shot | int | 否 | 每关系支持样本数，默认 `2` |
| n_query | int | 否 | 每任务查询数，默认 `1` |
| task_count | int | 否 | 生成任务数，默认 `5` |
| graph_space | string | 否 | 图谱来源 |
| relation_pool | string[] | 否 | 限定关系集合；空则从库中采样 |
| seed | int | 否 | 可复现采样 |

```json
{
  "n_way": 3,
  "k_shot": 2,
  "n_query": 1,
  "task_count": 5,
  "graph_space": "scientific_kg",
  "seed": 42
}
```

#### 5.2 输出 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| build_id | string | 本次构建 ID，可供后续 infer 引用 |
| tasks | object[] | 任务列表 |
| tasks[].task_id | string | 任务 ID |
| tasks[].relation | string | 本任务目标关系（或主关系） |
| tasks[].support | object[] | `{h,r,t}` 支持集 |
| tasks[].query | object[] | `{h,r}` 或 `{h,r,t?}`；`t` 可省略表示待预测 |

```json
{
  "status": "ok",
  "data": {
    "build_id": "mt_01",
    "tasks": [
      {
        "task_id": "task_1",
        "relation": "位于",
        "support": [
          {"h": "清华大学", "r": "位于", "t": "北京"},
          {"h": "北京大学", "r": "位于", "t": "北京"}
        ],
        "query": [
          {"h": "复旦大学", "r": "位于"}
        ]
      }
    ]
  },
  "error": null
}
```

### 6. 原型网络支持（少样本推断）

`POST /api/v1/few-shot/prototypical:infer`

基于支持集对查询头实体预测尾实体并生成候选三元组。

#### 6.1 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| algorithm | string | 否 | `prototypical`（默认）\| `matching` \| `relation_net` |
| build_id | string | 否 | 引用元任务构建结果 |
| task_id | string | 否 | 与 `build_id` 联用，指定任务 |
| relation | string | 条件必填 | 未传 build 时必填 |
| support | object[] | 条件必填 | `{h,r,t}[]`，未传 build 时必填 |
| query_heads | string[] | 条件必填 | 待预测头实体；或传 `queries: {h,r}[]` |
| top_k | int | 否 | 每个 query 返回候选数，默认 `1` |

```json
{
  "algorithm": "prototypical",
  "relation": "位于",
  "support": [
    {"h": "清华大学", "r": "位于", "t": "北京"},
    {"h": "北京大学", "r": "位于", "t": "北京"}
  ],
  "query_heads": ["复旦大学", "上海交通大学"],
  "top_k": 1
}
```

#### 6.2 输出 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| algorithm | string | 实际算法 |
| predictions | object[] | 预测结果 |
| predictions[].h | string | 头实体 |
| predictions[].r | string | 关系 |
| predictions[].t | string | 预测尾实体 |
| predictions[].score | float | `[0,1]` 置信度 |
| predictions[].candidates | object[] | 可选，top_k>1 时的候选 `{t,score}` |

### 7. 新关系快速学习

`POST /api/v1/few-shot/relations:adapt`

用户标注少量新关系正例后，快速适配并预测新三元组。

#### 7.1 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| relation | string | 是 | 新关系名 |
| support | object[] | 是 | 少量正例 `{h,r,t}`，`r` 可省略则用 `relation` |
| query_heads | string[] | 是 | 待补全头实体 |
| algorithm | string | 否 | 同 §6，默认 `prototypical` |
| top_k | int | 否 | 默认 `1` |
| persist_model | bool | 否 | 是否落盘适配后的轻量模型，默认 `false` |

```json
{
  "relation": "合作发表于",
  "support": [
    {"h": "李明", "t": "ACL"},
    {"h": "王芳", "t": "NeurIPS"},
    {"h": "赵强", "t": "AAAI"}
  ],
  "query_heads": ["陈刚", "周晓", "林伟"],
  "algorithm": "prototypical",
  "top_k": 1
}
```

#### 7.2 输出 `data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| relation | string | 新关系 |
| support_count | int | 使用的支持样本数 |
| model_id | string \| null | `persist_model=true` 时返回 |
| predictions | object[] | 同 §6.2，`r` 均为新关系 |

```json
{
  "status": "ok",
  "data": {
    "relation": "合作发表于",
    "support_count": 3,
    "model_id": null,
    "predictions": [
      {"h": "陈刚", "r": "合作发表于", "t": "ACL", "score": 0.84},
      {"h": "周晓", "r": "合作发表于", "t": "NeurIPS", "score": 0.81}
    ]
  },
  "error": null
}
```

## 五、联调验收清单（算法自测）

1. **对齐归一化**：同一文本换一张图，`image_raw.vector` 应变化；同一图改文本，`text_raw.vector` 应变化；`aligned[].after_dim` 恒等于 `target_dim`。  
2. **RL**：创建 env → train → metrics `series.length` 随 episode 增长；`success_rate ∈ [0,1]`。  
3. **少样本**：`meta-tasks:build` 返回非空 support/query；`prototypical:infer` 与 `relations:adapt` 对相同 support 给出稳定（可复现 seed）预测。  
4. 错误路径：缺图、缺 support、非法 policy 均返回 `status=error` 且不 5xx（除非内部故障）。

## 六、与前端页面对齐说明

| 页面 Tab | 调用时机 |
| --- | --- |
| 特征对齐与归一化 ·「编码 → 对齐与归一化」 | `align:normalize` |
| RL环境定义 ·「保存环境定义」 | `POST .../envs` |
| 策略网络 ·「启动训练」 | `policies:train`，成功后跳转监控 |
| 训练过程监控 | 轮询 `trainings/{job_id}/metrics`（建议 1–2s） |
| 元学习任务构建 ·「生成元学习任务」 | `meta-tasks:build` |
| 原型网络 ·「运行 …」 | `prototypical:infer`（可带 `build_id`） |
| 新关系快速学习 ·「快速学习并生成三元组」 | `relations:adapt` |
