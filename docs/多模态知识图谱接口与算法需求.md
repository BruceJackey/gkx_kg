# 多模态知识图谱接口与算法需求

> 范围更正：垂直领域知识图谱页面的 Mock、开发数据、TRS 图地址和算法接口，以 `docs/垂直领域知识图谱页面Mock与算法接口需求.md` 为准。本文件保留为其他多模态功能的扩展设计，不作为本次垂直领域页面联调依据。

> 用途：供算法开发机实现服务。接口完成后，当前前端页面只需将本地 Mock/`setTimeout` 替换为 HTTP 请求，即可接入真实数据。

### 1.3 边界说明

- **算法服务负责**：推理、训练、评估、向量化、检索、候选生成，以及返回可追溯证据。
- **业务服务负责**：数据集 CRUD、文件上传、权限、审核状态持久化、分页、操作审计。
- 单机原型可将两者实现为一个服务，但接口契约不得省略 `requestId`、模型版本、证据和状态字段。
- 当前多模态数据仅定义 `image + text`；不把音频、视频纳入本期接口。

## 2. 强制统一约定

### 2.1 基础协议

- Base URL：`http(s)://{host}:{port}/api/v1/mmkg`
- JSON 字段统一使用 **camelCase**，与当前 React 类型一致。
- 离线训练文件继续使用 `samples/clip/schema.json` 的 snake_case 字段；导入服务负责转换。
- 字符编码：UTF-8。
- 时间：ISO 8601 UTC，例如 `2026-08-30T14:20:30.123Z`。
- 置信度/相似度均为闭区间 `[0, 1]` 的有限小数，不允许百分数、`NaN` 或 `Infinity`。
- 无结果不是错误，返回空数组。
- 每个推理结果必须包含真实的 `modelName` 和 `modelVersion`，禁止写死展示值。

### 2.2 鉴权与请求头

```http
Authorization: Bearer <token>
X-Request-Id: req_01J...
Idempotency-Key: <uuid>   # 创建任务、审核决策等写操作必传
```

`X-Request-Id` 可由调用方提供；未提供时服务端生成，并在响应中返回。

### 2.3 统一成功响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_01J...",
  "data": {},
  "meta": {
    "modelName": "mmkg-ner",
    "modelVersion": "1.0.0",
    "elapsedMs": 86,
    "warnings": []
  }
}
```

列表响应的 `data` 固定为：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0,
  "hasMore": false
}
```

### 2.4 统一错误响应

```json
{
  "code": "INVALID_ARGUMENT",
  "message": "text 不能为空",
  "requestId": "req_01J...",
  "errors": [
    {
      "field": "text",
      "reason": "REQUIRED",
      "detail": "长度必须为 1～20000 个 UTF-16 code units"
    }
  ]
}
```

| HTTP | `code` | 场景 |
|---:|---|---|
| 400 | `INVALID_ARGUMENT` | 参数、文件类型、坐标或阈值非法 |
| 401 | `UNAUTHORIZED` | 未认证 |
| 403 | `FORBIDDEN` | 无数据集/模型权限 |
| 404 | `NOT_FOUND` | 资源不存在 |
| 409 | `STATE_CONFLICT` | 重复决策、版本冲突、任务状态不允许 |
| 413 | `PAYLOAD_TOO_LARGE` | 文本或图像超限 |
| 422 | `UNPROCESSABLE_CONTENT` | 文件合法但无法解码/推理 |
| 429 | `RATE_LIMITED` | 限流 |
| 500 | `INTERNAL_ERROR` | 服务内部错误 |
| 503 | `MODEL_UNAVAILABLE` | 模型未加载或依赖不可用 |

### 2.5 文本位置标准

`start`/`end`、`headStart`/`headEnd`、`tailStart`/`tailEnd` 必须遵守：

1. 以原请求 `text` 为基准；
2. 使用 **UTF-16 code unit 下标**，与浏览器 JavaScript `slice(start, end)` 一致；
3. 区间为左闭右开 `[start, end)`；
4. 必须满足 `text.slice(start, end) === 实体或概念原文`；
5. 算法不得先改写、去空格或 Unicode 归一化后再计算偏移；
6. 如算法内部使用 Python Unicode code point 下标，响应前必须转换为 UTF-16 下标。

### 2.6 图像坐标标准

为使当前页面可以直接使用百分比定位，所有视觉框统一返回：

```json
{ "x": 8.0, "y": 12.0, "w": 52.0, "h": 38.0 }
```

- 单位：相对原图宽高的百分比，范围 `[0, 100]`；
- 原点：图像左上角；
- `x/y`：框左上角；`w/h`：框宽高；
- 服务端必须先应用 EXIF Orientation，再基于纠正后的图像计算坐标；
- 必须满足 `x + w <= 100`、`y + h <= 100`；
- 响应同时返回纠正后 `imageWidth`、`imageHeight`；
- 视频暂不支持。

### 2.7 图像输入

视觉接口必须同时支持以下两种调用方式：

1. `multipart/form-data`：字段 `image` 为本地文件；
2. `application/json`：字段 `imageUrl` 为算法服务可访问的 URL/对象存储签名 URL。

二者必须且只能提供一个。支持 JPEG、PNG、WEBP；单图默认上限 20 MB、长边上限 8192 px。

## 3. P0 推理接口详细定义

## 3.1 文本实体定位

### 算法目标

从原文中识别人名、机构、事件、地点、产品、材料、技术等命名实体，返回实体类型、原文位置和置信度。类型应来自指定本体；无法映射时允许 `OTHER`，不得临时生成不稳定类型名。

### 请求

`POST /api/v1/mmkg/text/entities:locate`

```json
{
  "text": "清华大学张明教授在 ACL 2024 上发表了关于知识图谱与 GraphSAGE 嵌入的研究成果。",
  "language": "zh-CN",
  "ontologyId": "scientific-kg-v1",
  "entityTypes": ["ORG", "PER", "EVENT", "TECHNOLOGY"],
  "threshold": 0.5,
  "allowNested": false,
  "model": "default"
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `text` | string | 是 | 1～20000 UTF-16 code units |
| `language` | string | 否 | 默认 `auto`；支持 `zh-CN`、`en`、`auto` |
| `ontologyId` | string | 否 | 用于限制实体类型；为空使用服务默认本体 |
| `entityTypes` | string[] | 否 | 为空表示全部类型 |
| `threshold` | number | 否 | 默认 `0.5` |
| `allowNested` | boolean | 否 | 默认 `false` |
| `model` | string | 否 | 模型别名或版本，默认 `default` |

### 响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_entity_001",
  "data": {
    "text": "清华大学张明教授在 ACL 2024 上发表了关于知识图谱与 GraphSAGE 嵌入的研究成果。",
    "entities": [
      {
        "id": "ent_1",
        "text": "清华大学",
        "type": "ORG",
        "start": 0,
        "end": 4,
        "score": 0.98,
        "normalizedName": "清华大学",
        "kbId": null
      },
      {
        "id": "ent_2",
        "text": "张明",
        "type": "PER",
        "start": 4,
        "end": 6,
        "score": 0.94,
        "normalizedName": "张明",
        "kbId": null
      }
    ]
  },
  "meta": {
    "modelName": "mmkg-ner",
    "modelVersion": "1.0.0",
    "elapsedMs": 42,
    "warnings": []
  }
}
```

`entities[]` 最小必返字段：`id,text,type,start,end,score`。  
`color` 是前端展示属性，**不由算法返回**；前端按 `type` 映射颜色。

### 验收

- 每条 span 都能从原文精确切出；
- 相同文本多次出现时必须分别返回各自位置；
- 默认不返回重叠实体；开启 `allowNested` 后可返回嵌套实体；
- 空结果返回 `entities: []`。

## 3.2 视觉实体定位

### 算法目标

检测科研图像中的视觉对象/区域，例如图表区域、坐标轴、图例、标注文字、设备、材料结构等，返回百分比框和置信度。

### 请求

`POST /api/v1/mmkg/vision/entities:locate`

Multipart：

```text
image=<binary>                 必填，与 imageUrl 二选一
ontologyId=scientific-kg-v1    可选
labels=chart,axis,legend,text  可选，逗号分隔
threshold=0.5                  可选
maxDetections=100              可选
model=default                  可选
```

JSON：

```json
{
  "imageUrl": "s3://kg-mm/scipaper-clip-v2/train/0001.png",
  "ontologyId": "scientific-kg-v1",
  "labels": ["chart", "axis", "legend", "text"],
  "threshold": 0.5,
  "maxDetections": 100,
  "model": "default"
}
```

### 响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_vision_entity_001",
  "data": {
    "imageWidth": 1024,
    "imageHeight": 768,
    "entities": [
      {
        "id": "ve_1",
        "label": "图表区域",
        "type": "CHART",
        "x": 8.0,
        "y": 12.0,
        "w": 52.0,
        "h": 38.0,
        "score": 0.96,
        "normalizedLabel": "chart"
      }
    ]
  },
  "meta": {
    "modelName": "mmkg-object-detector",
    "modelVersion": "1.0.0",
    "elapsedMs": 176,
    "warnings": []
  }
}
```

最小必返字段：`id,label,x,y,w,h,score`。  
`color` 仍由前端按 `type/label` 生成。

### 验收

- 坐标符合第 2.6 节；
- 同类高度重叠框需经过 NMS；
- `id` 在本次响应内唯一，供视觉关系接口引用；
- 无目标返回 `entities: []`。

## 3.4 视觉概念定位

### 算法目标

对整张图进行多标签场景/视觉概念分类，按置信度降序返回，例如“实验室/科研场景”“显微镜/精密仪器”“医疗影像场景”。

### 请求

`POST /api/v1/mmkg/vision/concepts:locate`

输入方式同第 3.2 节，附加参数：

```json
{
  "imageUrl": "s3://kg-mm/medimage-clip-v1/train/0002.png",
  "ontologyId": "scientific-kg-v1",
  "candidateLabels": ["实验室 / 科研场景", "医疗影像场景", "工业检测场景"],
  "threshold": 0.2,
  "topK": 5,
  "model": "default"
}
```

`candidateLabels` 为空时使用服务端标签库；非空时执行零样本/受限分类。

### 响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_scene_001",
  "data": {
    "imageWidth": 512,
    "imageHeight": 512,
    "sceneConcepts": [
      {
        "id": "scene_1",
        "label": "医疗影像场景",
        "conceptId": "scene:medical_imaging",
        "score": 0.91,
        "rank": 1
      },
      {
        "id": "scene_2",
        "label": "实验室 / 科研场景",
        "conceptId": "scene:research",
        "score": 0.42,
        "rank": 2
      }
    ]
  },
  "meta": {
    "modelName": "mmkg-scene-classifier",
    "modelVersion": "1.0.0",
    "elapsedMs": 134,
    "warnings": []
  }
}
```

`sceneConcepts` 必须按 `score` 降序，`rank` 从 1 开始且连续。

## 3.5 通用关系定位

### 算法目标

识别“实体—实体”“实体—概念”“概念—概念”的语义关系。该接口强调节点类别，不要求页面高亮 span；底层可复用文本关系抽取模型。

### 请求

`POST /api/v1/mmkg/relations:locate`

```json
{
  "content": "清华大学张明教授研究知识图谱补全，与北京大学合作开展 GraphSAGE 实验。",
  "language": "zh-CN",
  "ontologyId": "scientific-kg-v1",
  "relationTypes": [],
  "threshold": 0.5,
  "maxRelations": 100,
  "includeCandidates": true,
  "model": "default"
}
```

### 响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_relation_001",
  "data": {
    "content": "清华大学张明教授研究知识图谱补全，与北京大学合作开展 GraphSAGE 实验。",
    "relations": [
      {
        "id": "rel_1",
        "head": "张明",
        "headId": "ent_2",
        "headKind": "entity",
        "headType": "PER",
        "relation": "就职于",
        "relationId": "employment",
        "tail": "清华大学",
        "tailId": "ent_1",
        "tailKind": "entity",
        "tailType": "ORG",
        "score": 0.94,
        "evidence": {
          "text": "清华大学张明教授",
          "start": 0,
          "end": 8
        }
      }
    ]
  },
  "meta": {
    "modelName": "mmkg-semantic-relation",
    "modelVersion": "1.0.0",
    "elapsedMs": 105,
    "warnings": []
  }

```

当前页面直接使用字段：`head,headKind,relation,tail,tailKind,score`；其余字段用于追踪、入图和审核，仍要求算法返回。

`headKind`/`tailKind` 枚举只能是：

- `entity`
- `concept`

## 3.6 文本关系定位

### 算法目标

从原文中抽取三元组，并精确返回主客体 span，供页面原文高亮。关系需尽量映射目标本体谓词。

### 请求

`POST /api/v1/mmkg/text/relations:locate`

```json
{
  "text": "LiFePO₄ 正极材料在 3.4V 平台下可逆容量达 170 mAh/g。",
  "language": "zh-CN",
  "ontologyId": "scientific-kg-v1",
  "relationTypes": ["理论容量", "工作电压"],
  "threshold": 0.5,
  "extractEntities": true,
  "model": "default"
}
```

### 响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_text_relation_001",
  "data": {
    "text": "LiFePO₄ 正极材料在 3.4V 平台下可逆容量达 170 mAh/g。",
    "triples": [
      {
        "id": "triple_1",
        "head": "LiFePO₄",
        "headId": "ent_1",
        "headType": "MATERIAL",
        "relation": "理论容量",
        "relationId": "theoretical_capacity",
        "tail": "170 mAh/g",
        "tailId": "ent_2",
        "tailType": "VALUE",
        "headStart": 0,
        "headEnd": 7,
        "tailStart": 28,
        "tailEnd": 37,
        "score": 0.92,
        "sentence": "LiFePO₄ 正极材料在 3.4V 平台下可逆容量达 170 mAh/g。"
      }
    ]
  },
  "meta": {
    "modelName": "mmkg-text-re",
    "modelVersion": "1.0.0",
    "elapsedMs": 92,
    "warnings": []
  }
}
```

当前页面直接使用字段：`head,relation,tail,headStart,headEnd,tailStart,tailEnd,score`。

### 验收

- 主客体文本必须分别等于原文对应 slice；
- 关系方向必须稳定，不能同一关系随机反转；
- 同一主客体存在多种关系时分别返回；
- 关系无法映射本体时，`relationId` 可为 `null`，但 `relation` 必须是可读文本。

## 3.7 视觉关系定位

### 算法目标

先检测图像对象，再判断对象间的空间或语义谓词，例如 `above`、`describes`、`labels`。响应须包含主客体框，以便页面绘制框和连线。

### 请求

`POST /api/v1/mmkg/vision/relations:locate`

除图像输入外支持：

```json
{
  "imageUrl": "s3://kg-mm/scipaper-clip-v2/train/0002.png",
  "predicateTypes": ["above", "below", "left_of", "right_of", "contains", "describes", "labels"],
  "threshold": 0.5,
  "maxRelations": 100,
  "reuseDetections": [],
  "model": "default"

```

## 4.1 离线训练数据契约

算法训练必须直接读取 `ImageTextPairSchema@v1.1`：

```json

  "id": "scipaper-train-0001",

  "source": "arXiv:2310.00001",
  "lang": "en",
  "width": 1024,
  "height": 768,
  "clip_score": 0.41
}
```

| 离线字段 | API/UI 字段 | 必填 | 说明 |
|---|---|---:|---|
| `id` | `id` | 是 | 图文对唯一 ID |
| `image` | `imageUrl` | 是 | URL、对象存储 Key 或相对路径 |
| `caption` | `caption` | 是 | 与图像对齐文本，建议不超过模型 tokenizer 上限 |
| `split` | `split` | 是 | `train/val/test` |
| `tags` | `tags` | 否 | 标签数组 |
| `source` | `source` | 否 | DOI、专利号、检查号等来源 |
| `lang` | `lang` | 否 | `zh/en`，默认 `en` |
| `width` | `width` | 否 | 像素宽 |
| `height` | `height` | 否 | 像素高 |
| `clip_score` | `clipScore` | 否 | 预训练图文 cosine |

训练要求：

- `train` 参与对称 InfoNCE；
- `val` 至少计算 Image→Text、Text→Image 的 Recall@1/5/10；
- `test` 只评测，不参与早停；
- 不得把同一来源的近重复图片拆到不同集合造成数据泄漏；
- 无法访问的 `image`、空 `caption`、重复 `id` 必须进入质量报告。

## 10. 异步任务统一契约

训练、导入、评估、预处理、索引、补全和文档转写均使用同一任务模型：

```json
{
  "jobId": "job_001",
  "jobType": "training",
  "status": "running",
  "progress": 63,
  "stage": "evaluating",
  "message": "正在计算验证集双向 Recall@K",
  "createdAt": "2026-08-30T14:00:00Z",
  "startedAt": "2026-08-30T14:00:02Z",
  "updatedAt": "2026-08-30T14:20:30Z",
  "finishedAt": null,
  "result": null,
  "error": null
}
```

- `progress` 为 `0～100`；
- 状态只能单向流转：`queued → running → succeeded/failed/cancelled`，暂停任务允许 `running ↔ paused`；
- 前端一期每 1～2 秒轮询；后续可增加 SSE，不作为首版阻塞条件；
- 任务失败时 `error` 必须含 `code,message,retryable`；
- 任务结果和日志至少保留 30 天。

## 12. 前端接入前置工作

当前仓库没有真实 `fetch/axios` 调用、统一 HTTP 客户端或 Vite 代理。算法接口上线并不等于页面自动联网，前端需一次性增加：

```text
src/app/api/client.ts        # Base URL、Bearer、超时、统一响应/错误解析
src/app/api/mmkg.ts          # 本文接口的类型化调用函数
src/app/types/mmkg.ts        # 第 11 节共享类型
```

要求：

- Base URL 从 `VITE_MMK_API_BASE_URL` 读取，不写死开发机 IP；
- 开发环境配置 Vite proxy 或算法服务开放指定前端域名的 CORS；
- HTTP 客户端统一注入 `Authorization`、`X-Request-Id`；
- 30 秒内同步接口使用 `AbortController` 超时；
- 页面卸载或重新发起请求时取消旧请求，避免旧结果覆盖新结果；
- 删除各组件内规则常量、随机结果和假进度，仅保留示例输入；
- API envelope 以本文 `{code,message,requestId,data,meta}` 为唯一规范。仓库历史 Mock 的其他响应样式不作为兼容要求。

## 13. 算法交付要求

每个算法服务交付物必须包括：

1. 可部署服务与启动说明（Dockerfile/Compose 或等价方式）；
2. OpenAPI 3.0 文档，字段与本文一致；
3. 模型名称、版本、权重来源、许可证和校验和；
4. 训练/验证数据版本与预处理配置；
5. 至少 5 个成功样例、1 个空结果样例、1 个非法输入样例；
6. 自动化契约测试；
7. 真实性能报告：硬件、样本规模、P50/P95/P99、吞吐、显存；
8. 指标报告与阈值选择依据；
9. 日志中包含 `requestId`，但不得记录完整敏感文本、原图或令牌；
10. 失败降级说明与可重试错误清单。

### 13.1 最低指标口径

| 算法 | 必报离线指标 |
|---|---|
| 文本实体定位 | Precision、Recall、F1（严格 span + type） |
| 视觉实体定位 | mAP@0.5、mAP@0.5:0.95 |
| 文本概念定位 | span F1、概念归一化 Accuracy/Recall@K |
| 视觉概念定位 | Top-1、Top-5、多标签 mAP（按任务类型选择） |
| 文本/通用关系定位 | 三元组 micro/macro F1、关系分类 F1 |
| 视觉关系定位 | Recall@50/100、mean Recall@50/100 |
| 图文检索 | I→T 与 T→I 的 Recall@1/5/10、Median Rank |
| 图像描述 | CIDEr、SPICE/BLEU，并提供人工准确性抽检 |
| 图谱补全 | MRR、Hits@1/3/10（filtered setting） |
| 多模态知识检索 | nDCG@10、MRR、分模态 Recall@K、去重准确率 |
| 垂直图谱关系推理 | Precision/Recall/F1；趋势需方向准确率与时间切分回测 |

指标门槛由业务验收集确定；在没有标注验证集时不得宣称“达到生产精度”。

### 13.2 性能目标

| 接口类型 | 目标 |
|---|---|
| 文本实体/概念/关系，文本 ≤ 2000 字 | P95 ≤ 2 s |
| 单图实体/概念/视觉关系，图像 ≤ 4K | P95 ≤ 5 s |
| 跨模态 Top-K 检索，百万级向量 | P95 ≤ 500 ms（索引已热） |
| 多附件知识库混合检索 | P95 ≤ 3 s |
| 同步接口超时 | 30 s |
| 服务健康检查 | `GET /healthz` 与 `GET /readyz` |

性能目标不应通过返回缓存 Mock 达成；性能测试必须记录模型、硬件和并发数。

## 14. 联调与验收顺序

1. 算法机先提交 OpenAPI 文件和固定样例响应；
2. 前端使用样例响应完成类型检查和渲染；
3. 联调文本偏移与视觉坐标，这是最容易导致页面错位的部分；
4. 接入七个同步定位接口；
5. 接入补全候选列表与审核决策；
6. 接入图文检索、自动描述、质量评估；
7. 最后接入训练、索引、导入等异步任务；
8. 清除页面中的规则 Mock、随机数、`setTimeout` 假进度；
9. 用真实数据完成一轮端到端验收：
   - 图文对导入；
   - 预处理和 CLIP 训练；
   - 索引构建与双向检索；
   - 文本/图像实体、概念、关系定位；
   - 生成补全候选；
   - 人工通过/拒绝并回写状态。
   - 图片/表格/公式反向与混合检索；
   - 垂直领域企业图谱及带证据推理。

### 最终验收条件

- 当前页面展示所需字段均来自真实接口，不再依赖静态 Mock；
- 所有文本高亮位置准确，所有视觉框不偏移；
- 刷新页面后数据、任务状态和审核结果不丢失；
- 每个结果可追溯到模型版本和输入证据；
- 空结果、模型失败、超时、无权限均有明确错误响应；
- 接口返回字段与本文一致，前端不需要基于算法版本编写多套解析逻辑。
