# 编码模型训练 · 辅助信息融合 · 算法接口需求

> **用途**：供算法侧按契约实现 HTTP 接口。前端为审计目录「知识表示学习 / 辅助信息」专用页，当前本地 Mock，联调时替换为真实请求。  
> **前端路由**：`/graph-construction-engine/auxiliary-info-encoding`  
> **前端组件**：`bohrium-space/.../auxiliary-info-encoding/`  
> **目录叶子**：  
> - `fp-100-222` 文本描述信息融合（`?step=aux&aux=text`）  
> - `fp-100-223` 实体类型信息融合（`?step=aux&aux=type`）  
> - `fp-100-224` 多模态信息集成（`?step=aux&aux=mm`）  
> **交互形态**：四步在**同一页面流水线**中串联，不是三个独立页：  
> 1）选编码模型 + 超参数 → 2）三类辅助信息**可选启用**（启用则必填）→ 3）发起训练 → 4）用已训练 checkpoint 做链接预测  
> **建议 Base**：独立服务 `http://127.0.0.1:18230`；生产经网关 `http://127.0.0.1:30080` 原样转发（与 mm-fusion `18200` / 关系度量 `18210` / 元学习推理 `18220` 分端口，或挂同一网关 `/api/v1`）

## 0. 算法语义（请务必先对齐）

**vanilla 编码模型本身吃不到辅助信息。** TransE / TransH / DistMult / ComplEx / ConvE 的打分函数只依赖结构三元组 \((h,r,t)\)。

本模块要求的是：**以所选编码模型为结构编码器，再按开关外挂辅助通道**，联合学习更丰富的实体向量。关闭全部开关时，退化为纯结构 KGE 训练。

| 开关 | 产品能力 | 建议实现（可替换，需在 `fusion` 回显） | 参考 |
| --- | --- | --- | --- |
| `use_text` | 实体文本描述与结构共同学习 | 描述编码器（CNN / Transformer / 哈希回退）→ 与结构向量拼接或相加；结构损失 + 描述对齐损失 | DKRL |
| `use_type` | 实体类型作为约束或特征 | 类型投影 / 类型嵌入拼接；不合类型的三元组加惩罚 | TKRL |
| `use_mm` | 图像、音频等模态集成 | 图像 OpenCLIP（失败哈希）；音频可用 log-mel + 小 CNN 或哈希；对齐到实体向量 | IKRL / MKBE |

**融合发生在训练期**，写入 checkpoint。推理必须使用**同一 checkpoint**，不得在 infer 时偷偷关掉已训练的通道，也不得在 infer 时新开训练期未启用的通道。

建议实体最终表示：

\[
\mathbf{e} = f_{\text{struct}}(e) \oplus \alpha_t \mathbf{e}^{\text{text}} \oplus \alpha_y \mathbf{e}^{\text{type}} \oplus \alpha_m \mathbf{e}^{\text{mm}}
\]

未启用的通道 \(\alpha=0\) 且不占参数。关系向量仍由结构模型学习。ComplEx 的结构部分在 \(\mathbb{C}^d\)，辅助向量建议映到同维度后在实部拼接，或统一先映到实数再 ComplEx 打分——实现自选，但必须在 `embedding_space` 回显。

## 统一约定

### 响应壳

与现网关一致，默认：

```json
{"status":"ok","data":{},"error":null}
```

也兼容：

```json
{"code":"OK","message":"success","requestId":"req_xxx","data":{}}
```

失败：`status=error`（或 `code≠OK`），`error`/`message` 为可读中文原因，HTTP `400/404/422/500`。

鉴权：`Authorization: Bearer <token>` + `X-Request-Id`。

字段 **snake_case**。

### 异步任务

训练通常异步。提交后返回 `job_id`，用 `GET /api/v1/jobs/{job_id}` 或本模块 `GET /api/v1/kge-aux/trainings/{job_id}` 轮询。

| `status` | 含义 |
| --- | --- |
| `queued` / `running` | 进行中 |
| `succeeded` / `success` / `completed` | 完成，`data.checkpoint` 可用 |
| `failed` / `error` | 失败，`error` 说明原因 |
| `cancelled` | 已取消 |

**小规模演示**（`epochs ≤ 8` 且图规模为内置 `scientific_kg`）允许同步：HTTP 200 且 `status=ok` 时直接带上 `checkpoint`，`job_id` 仍建议返回。前端两种都能接。

`checkpoint_id` 建议缓存 **≥ 4 小时**（或进程内存 + 落盘均可）。过期后 infer 返回 404，前端提示重新训练。

### 图数据

| 字段 | 说明 |
| --- | --- |
| 缺省 | 内置演示图 `scientific_kg`（含大学/人物/会议等少量三元组即可） |
| `graph_id` / `graph_space` | 可选；如 `gkx_rag` 时从 TRS 采样三元组 |

辅助信息只覆盖**部分实体**即可：未覆盖实体仅用结构向量，不要 400。

## 二、发起训练

`POST /api/v1/kge-aux/trainings`

### 2.1 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| model_id | string | **是** | 来自模型库 |
| dim | int | 否 | 嵌入维度，默认 `200`，范围 `[32, 512]` |
| lr | float | 否 | 学习率，默认 `0.01`，范围 `(0, 0.1]` |
| batch_size | int | 否 | 默认 `128`，范围 `[16, 1024]` |
| epochs | int | 否 | 默认 `50`；演示建议 `8` |
| embedding_space | string | 否 | `real` \| `complex`；缺省用模型 `preferred_space`。`complex`+TransE 允许但需在日志/回显中注明为扩展 |
| margin | float | 否 | 平移模型间隔，默认 `1.0` |
| optimizer | string | 否 | `adam` / `sgd` / `adagrad` / `adamw`，默认 `adam` |
| neg_samples | int | 否 | 负采样数，默认 `32` |
| seed | int | 否 | 复现 |
| graph_id / graph_space | string | 否 | 结构三元组来源 |
| triples | triple[] | 否 | 若传入则**优先用该批三元组**训练，不再从图采样；演示前端可不传 |
| use_text | bool | 否 | 默认 `false` |
| text_items | text_item[] | `use_text=true` 时**是** | 至少 1 条 |
| use_type | bool | 否 | 默认 `false` |
| type_items | type_item[] | `use_type=true` 时**是** | 至少 1 条 |
| use_mm | bool | 否 | 默认 `false` |
| mm_items | mm_item[] | `use_mm=true` 时**是** | 至少 1 条 |
| text_encoder | string | 否 | 建议 `hash` / `cnn` / `transformer`；缺省服务端自选 |
| type_fusion | string | 否 | 建议 `concat` / `project` / `constraint` |
| mm_fusion | string | 否 | 建议 `concat` / `gate` |

## 四、链接预测推理

| --- | --- | --- |
| 缺 `checkpoint_id` / `h` / `r` | 400 | |

## 七、辅助信息如何真正进 TransE（实现约束）

算法同学实现时请满足下面可验收行为，避免「开关开了但只跑纯 TransE」。

### 7.1 纯结构基线（三开关全关）

- 损失仅为结构损失（TransE：正负样本 margin ranking）。
- `aux_flags=[]`，`fusion.*.` 全 `null`。
- 同一 `seed` + 同一图，两次训练 `mrr` 应接近。

### 7.2 仅文本（`use_text=true`）

- 每个 `text_items.entity` 必须产生 \(\mathbf{e}^{\text{text}}\)。
- 结构损失仍在；另加描述重建或结构-描述对齐损失（\(\lambda_{\text{text}}\) 默认 `0.5`，可写死）。
- 对比实验：同一结构数据下，给「李明」一条明确写着「就职于清华大学」的描述，infer `(李明, 就职于, ?)` 时「清华大学」得分应 **高于** 无描述的对照 run（允许小规模噪声，但排序应稳定更好）。
- `reason` 含「文本」或 `text`。

### 7.3 仅类型（`use_type=true`）

- 训练或打分阶段使用类型：投影、拼接或约束惩罚至少一种，并在 `fusion.type` 写明。
- 演示约束：关系 `就职于` 的合理尾类型为 `机构`；若候选含 `ACL(会议)` 与 `清华大学(机构)`，后者分数应更高。
- `reason` 含类型信息，如 `类型约束 人物→机构`。

### 7.4 仅多模态（`use_mm=true`）

- 图像/音频编码进实体向量（url 失败则哈希，保证能跑通）。
- 与结构联合训练；`aux_flags` 含 `mm`。
- 不要求开放域 SOTA，但同一实体有图无图的向量不得完全相同（除非哈希碰撞）。

### 7.5 多通道同时开

- 损失为结构 + 各通道损失加权和。
- `aux_flags` 为实际启用集合的排序稳定列表，建议固定顺序 `["text","type","mm"]` 的子集。

## 八、联调顺序建议

1. `GET .../models` → 渲染模型卡片  
2. `POST .../trainings`（先三开关全关、`epochs=8`）→ 拿到 `checkpoint_id`  
3. `POST .../links:infer`（`h=李明, r=就职于`）→ 表格有 `h/r/t/score`  
4. 再跑一次 `use_text+use_type` 的训练 → infer 的 `aux_flags` 与 `reason` 变化可观察  
5. 异步：大 `epochs` 时 `GET .../trainings/{job_id}` 直到 `succeeded`

耗时：`epochs≤8` 的演示训练目标 **&lt; 30s**；infer **&lt; 3s**。

## 十、前端字段映射（实现参考）
