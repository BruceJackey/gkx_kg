# dp 侧关系挖掘可行性清单

对照：`实体关系表（分工表）.xlsx` 中负责方为 **dp / DP** 的页  
口径：

1. 仅看 dp 相关关系（文献&活动、论文&专利、事件）  
2. **忽略因缺实体而无法立边的项**（如数据集、科学工具、实验设备、竞赛、学术会议、研究任务等）  
3. 「可挖」= 现有 MySQL/dwd 表中有 ID 或稳定关联字段可直接/间接构图  
4. 数据源：样例库 `gkx`（`183.240.141.251:3318`）表结构与抽样填充情况

## 2. 可挖

两侧实体存在，且有明确关联字段（ID 或结构化外键/对照键）。

| 页 | 源 → 目标 | 关系 | 挖掘路径 | 数据备注 |
|---|---|---|---|---|
| 文献&活动 | 期刊 → 文献 | 收录 | `dwd_zh_paper.publication_id` / `issn` → `dwd_zh_journal` | 样例约 5303/20000 能命中期刊表；本体已有「发表期刊」 |
| 文献&活动 | 文献 → 科学对象（≈化合物） | 研究 | `dwd_substance_paper(substance_id, paper_id)`；专利侧 `dwd_substance_patent` | 表结构可挖；样例 `paper_id` 填充极差，上线前需验实库 |
| 论文&专利 | 机构 → 专利 | 发布/申请 | `dwd_patent_applicants.name`、`first_applicant_name`、`assignees` → 机构名对齐 | 申请人名字段填充高；需机构名归一 |

## 3. 弱挖

无稳定 FK，仅有自由文本 / JSON / 可解析字符串，可做启发式对齐，召回与噪声需评估。

| 页 | 源 → 目标 | 关系 | 挖掘路径 | 限制 |
|---|---|---|---|---|
| 论文&专利 | 机构 → 论文 | 发布 | `dwd_zh_author.institution` / `affiliation` 文本 → 机构名匹配 | 约 73% 有值；无 `org_id`；单位写法不规范 |
| 事件 | 事件 → 机构 | 主体 / 参与（会展主办方） | 解析 `dwd_event.organizer`（如「主办：国药励展、药渡…」）→ 机构 | 仅约 20 条，且是论坛/展会，**不等于**分工表「资讯突发」 |
| 事件（若改绑新闻） | 新闻 → 企业 | 关联企业 | `dwd_news_base.xgqyxx` JSON（含 `company_id`） | 只能得到新闻–企业，**不能**直接当事件–人才/论文/专利/项目 |
| （旁路，非事件） | 项目 → 论文/专利 | 产出关联 | `dwd_zh_project_output.output_journal_articles` / `output_patents` JSON 标题级对齐 | 属项目成果，不是事件关系；标题匹配弱 |

## 4. 挖不动

两侧实体在本体中可存在，但现库**没有可用关联字段**，字段关联挖掘不可行（需 NLP 新抽或新落表）。

| 页 | 源 → 目标 | 关系 | 原因 |
|---|---|---|---|
| 论文&专利 | 论文/专利 → 技术 | 提出 | 论文有 `classification.keywords`，专利有 `keywords`/IPC/CPC；但「技术」节点主要来自 `dwd_org_tech_tag.org_tag`，实为「高新技术企业/专精特新」等**企业资质标签**，非技术单元，无法对齐；更无法区分「提出」 |
| 论文&专利 | 论文/专利 → 技术 | 使用 | 同上；字段无法区分「使用」vs「提出」 |
| 事件 | 事件 → 人才 | 参与 | `dwd_event` 无人名 / scholar_id |
| 事件 | 事件 → 人才 | 主体 | 同上 |
| 事件 | 事件 → 机构 | 参与/主体（突发语义） | 会展 `organizer` 撑不起资讯突发；资讯表 `dwd_information` 样例 `author`/`keywords` 为空 |
| 事件 | 事件 → 中文/外文论文 | 关联 | 事件表无论文 ID/标题列表 |
| 事件 | 事件 → 专利 | 关联 | 事件表无专利号/ID |
| 事件 | 事件 → 国内/国外项目 | 关联 | 事件表无项目 ID/编号 |

## 5. 汇总

| 类别 | 条数（约） | 代表关系 |
|---|---:|---|
| 可挖 | 3 | 期刊收录、物质–文献/专利、机构–专利 |
| 弱挖 | 3～4 | 机构–论文、事件主办方、新闻–企业、项目产出 JSON |
| 挖不动 | 6+ | 论文/专利→技术（提出/使用）；事件→人才/论文/专利/项目 |

**结论：** dp 在去掉缺实体项后，字段级可落地的主要是文献期刊链与专利/物质机构链；**技术提出/使用**与**事件多跳关联**当前库挖不动，需要补抽取链路或新关系表后再进图。
